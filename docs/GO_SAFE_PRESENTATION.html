Urban Transit Analysis

Why Traditional Mobility Fails

Addressing core safety risks, driver spoofing, and passenger anxiety in high-density urban centers.

The Vulnerabilities

  • Driver Impersonation: Rogue drivers picking up wrong passengers due to missing physical verification.
  • Gender Safety Gaps: Female passengers in Egypt often face discomfort without guaranteed female-only options.
  • Slow Polling Latency: Traditional HTTP polling causes missed ride notifications or race condition collisions.
RESULT: Unpredictable transit & compromised user safety

The Go Safe Engineering

  • Mandatory 4-Digit Handshake PIN: Trips cannot physically initiate in software until passenger delivers PIN to driver.
  • Go Safe Her (100% Female): Strict biometric and National ID OCR onboarding to guarantee women-only safety.
  • WebSocket Real-Time Dispatch: Firestore live event listeners notify driver devices in less than 100 milliseconds.
RESULT: Zero-trust, atomic, and verifiable urban mobility
End-To-End Experience

How It Goes: The Ride Lifecycle

From initial login to atomic trip claim, handshake verification, and completion.

01

Intelligent Onboarding

Default login screen (Username or Mobile + Password). Interactive "Register Now" modal directs user to Client or Captain onboarding with 14-digit National ID and vehicle specs.

02

Fleet Booking & Preview

Passenger enters pickup & drop-off. Selects either Go Safe Standard or Go Safe Her. Dynamic formula preview: Base 15 EGP + 10 EGP/km (Min 25 EGP).

03

Instant Driver Alert

Firestore document is created with status: 'requested'. Active drivers' streamAvailableRides listeners trigger instantly with haptic vibration and 30s modal.

04

Atomic Trip Acceptance

Captain taps "Accept Trip". A Firestore Transaction locks the trip to that driver. Prevents race conditions. Rider screen instantly updates with captain name, vehicle plate, and secret PIN.

05

Handshake Safety PIN

Driver arrives at pickup. Passenger provides their 4-digit PIN. Driver enters PIN in app; once validated, trip switches to in_progress and live GPS stream begins.

06

Safe Arrival & Rating

Captain completes the trip. Exact fare is settled, digital itemized receipt is displayed to rider, and a two-way 5-star rating with safety badges is recorded into Firestore.

Zero-Trust Security

Security Engineering & Rules

709 lines of production-grade Firestore Security Rules enforcing integrity at the cloud engine.

Role-Based Access Control (RBAC)

Strict checks ensuring riders cannot view unassigned drivers or manipulate driver status, and drivers cannot access other drivers' wallets.

Immutable Financial Calculations

Client applications cannot dictate arbitrary fares. All ride prices are validated against the formula: max(25.00, 15.00 + km * 10.00).

PII Shielding & Privacy

National ID numbers and contact phone numbers are concealed from open queries and only visible to the assigned party during an active ride.

firestore.rules (Excerpt) 709 Lines Active 
match /rides/{rideId} {
  allow create: if isAuthenticated() 
    && request.resource.data.rider_id == request.auth.uid
    && request.resource.data.status == 'requested';

  allow update: if (
    // Captain accepts atomically
    isDriver() 
    && resource.data.status == 'requested'
    && request.resource.data.status == 'accepted'
    && request.resource.data.driver_id == request.auth.uid
  ) || (
    // Handshake PIN verification
    resource.data.driver_id == request.auth.uid
    && request.resource.data.status == 'in_progress'
  );
}
