1. Executive Summary & System Overview

Go Safe (جو سيف) is a modernized, cloud-native ride-hailing and verified urban mobility ecosystem specifically engineered to address trust, security, and gender-safety vulnerabilities in metropolitan transportation networks.

Core Innovation: Go Safe combines sub-100ms real-time cloud dispatch with an immutable 4-digit handshake safety PIN, ensuring that trips cannot physically or digitally initiate without explicit mutual physical confirmation between driver and rider.

Sample 1: Instant Trip Dispatch & Streamer (mobile_app/lib/core/services/firebase_service.dart)

Demonstrates creating a ride document with metadata and broadcasting it instantly to all listening driver devices.

Future<String> requestRide({
  required String pickupAddress,
  required double pickupLat,
  required double pickupLng,
  required String dropoffAddress,
  required double dropoffLat,
  required double dropoffLng,
  required double distanceKm,
  required double fareEgp,
  required String tier, // 'standard' or 'rafik_girl' (Go Safe Her)
}) async {
  final user = currentUser;
  if (user == null) throw Exception('User not authenticated');

  // Generate unpredictable 4-digit safety handshake PIN
  final randomPin = (1000 + Random().nextInt(9000)).toString();

  final docRef = await firestore.collection('rides').add({
    'rider_id': user.uid,
    'tier': tier,
    'status': 'requested',
    'pickup_address': pickupAddress,
    'pickup_lat': pickupLat,
    'pickup_lng': pickupLng,
    'dropoff_address': dropoffAddress,
    'dropoff_lat': dropoffLat,
    'dropoff_lng': dropoffLng,
    'fare_egp': fareEgp,
    'pin': randomPin,
    'driver_id': null,
    'requested_at': FieldValue.serverTimestamp(),
  });

  return docRef.id;
}

Sample 2: Atomic Race-Condition-Free Trip Acceptance (Firestore Transactions)

Guarantees that when multiple captains tap "Accept" concurrently, exactly one driver wins the ride without duplicate allocations.

Future<bool> acceptRide({
  required String rideId,
  required String driverId,
  required String driverName,
  required String vehiclePlate,
}) async {
  return firestore.runTransaction<bool>((transaction) async {
    final rideRef = firestore.collection('rides').doc(rideId);
    final snapshot = await transaction.get(rideRef);

    if (!snapshot.exists || snapshot.get('status') != 'requested') {
      return false; // Another captain already locked the ride
    }

    transaction.update(rideRef, {
      'status': 'accepted',
      'driver_id': driverId,
      'driver_name': driverName,
      'vehicle_plate': vehiclePlate,
      'accepted_at': FieldValue.serverTimestamp(),
    });

    transaction.update(firestore.collection('drivers').doc(driverId), {
      'is_busy': true,
    });

    return true;
  });
}

Sample 3: Production Declarative Security Rules (firestore.rules)

Excerpt from the 709-line security rules enforcing RBAC and mathematical fare validation at the cloud database engine.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    match /rides/{rideId} {
      // Only authenticated riders can create trips
      allow create: if request.auth != null 
        && request.resource.data.rider_id == request.auth.uid
        && request.resource.data.status == 'requested'
        && request.resource.data.fare_egp >= 25.0;

      // Driver claims or updates trip stage
      allow update: if (
        // 1. Atomic claim
        resource.data.status == 'requested'
        && request.resource.data.status == 'accepted'
        && request.resource.data.driver_id == request.auth.uid
      ) || (
        // 2. In-trip progression
        resource.data.driver_id == request.auth.uid
        && request.resource.data.status in ['arrived', 'in_progress', 'completed']
      );
    }
  }
}
